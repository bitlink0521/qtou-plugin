# 轻投：尽调报告

先按 `qtou-connect` 技能连上轻投。只走 qtou MCP 工具，只读不改库，返回 `isError` 时把 code 和 message 如实转告。

## 执行清单

1. **检索**：`agent_documents_search({ q: "<项目名或文档名>" })`，或 `{ projectId }` 列出该项目全部文档。`q` 和 `projectId` 至少给一个；参数名只认 `q`、`projectId`。
   - 精确匹配 0 条时服务端自动按错别字容错（返回 `matchMode=fuzzy`），结果要注明「按近似匹配找到」。
   - `tied: true` 表示同分并列；查询里没有项目名、多个项目并列时，必须让用户确认是哪个项目，或带 `projectId` 重查。
   - 把命中列给用户：文档名、`fileId`、`readable`。返回的 `path` 只用于展示，读正文一律用 `fileId`。
   - 0 条就如实说没找到，请用户换关键词。
2. **读正文**：对属于该项目、`readable: true` 的每份文档调 `agent_documents_content({ fileId, maxChars })`。
   - `textStatus=no_text_layer`（扫描件或图片）不算不可读：用 `agent_documents_pages({ fileId, pages: [n, n+1] })` 按页看图读，每次 1–2 页，按 `pageCount` 读完需要的页。逐字照抄，看不清写「看不清」，不猜；底稿记下页码。Word / PPT 没有页面图，按不可读处理。
   - 返回 `FAILED_PRECONDITION`（无实体文件）、跨租户或无权限：记为「未读」及原因，其余照常，不绕道读文件。
3. **定写法**（先读 [DD-REPORT-WRITING.md](DD-REPORT-WRITING.md) 第 0 节）：
   ① 不带 `projectId` 搜「尽调报告 / 投资建议书 / 尽职调查 / 投决报告」等，挑 1–3 份最完整的读全文，学结构、用词和排版，以它为准；
   ② 找不到就开写前问用户有没有模板或范本；
   ③ 都没有，才用 DD-REPORT-WRITING.md 第 1–11 节兜底。
   范本只学写法，不搬它的公司事实和数字。
4. **写报告**：事实和数字只用第 2 步读回的本项目材料。
   - 材料里没有的，在缺信息的那一处写「待补」，不推算、不补外部常识；问题清单只放材料里有但需向企业核实的事项。
   - 正文不加引文、脚注、来源表、「编制说明」等证明或免责文字。
   - 另存工作底稿：每个事实或数字 → 文档名、fileId、原文逐字摘录、自算数的算式，只供自检，不放进报告。
5. **自检**：按 DD-REPORT-WRITING.md 第 12 节逐条核对，每个数字都能在材料原文找到或由其算出，不过就改到过为止，不交半成品。

## 交付

- **报告全文直接贴在对话里**（不是摘要），不能只给文件路径或链接；用户另要文件时可以另存。
- 交付消息里（不写进报告）说明：参照了哪份范本（文档名 + fileId / 用户模板 / 插件兜底规范）；这是初稿、待投资经理复核；未读文档及原因；「待补」清单；材料是模拟或测试数据时一并说明。
