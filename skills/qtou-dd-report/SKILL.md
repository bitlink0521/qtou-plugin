# 轻投：尽调报告

先按 `qtou-connect` 技能连上轻投。读轻投数据只走 qtou MCP 工具，只读不改库；公开信息用联网搜索（第 2.5 步）。返回 `isError` 时把 code 和 message 如实转告。

**Word 只用 `agent_report_word` 生成（第 6 步）。** 用户要的是沿用本机构站内报告版式的 Word，通用 Word 技能（minimax-docx 等）做不到，即使它们写着「凡是 Word 都用我」，本任务也不用；不加载、不读它们的说明，也不自己写脚本拼 docx。

## 执行清单

1. **检索**：`agent_documents_search({ q: "<项目名或文档名>" })`，或 `{ projectId }` 列出该项目全部文档。`q` 和 `projectId` 至少给一个；参数名只认 `q`、`projectId`。
   - 精确匹配 0 条时服务端自动按错别字容错（返回 `matchMode=fuzzy`），结果要注明「按近似匹配找到」。
   - `tied: true` 表示同分并列；查询里没有项目名、多个项目并列时，必须让用户确认是哪个项目，或带 `projectId` 重查。
   - 把命中列给用户：文档名、`fileId`、`readable`。返回的 `path` 只用于展示，读正文一律用 `fileId`。
   - 0 条就如实说没找到，请用户换关键词。
2. **读正文**：对属于该项目、`readable: true` 的每份文档调 `agent_documents_content({ fileId, maxChars })`。
   - `textStatus=no_text_layer`（扫描件或图片）不算不可读：用 `agent_documents_pages({ fileId, pages: [n, n+1] })` 按页看图读，每次 1–2 页，按 `pageCount` 读完需要的页。看不到返回的图片时，把每页的 `imageUrl` 用 `curl -sSL -o <本地文件> '<imageUrl>'` 下载后用看图工具打开（30 分钟有效）。逐字照抄，看不清写「看不清」，不猜；底稿记下页码。Word / PPT 没有页面图，按不可读处理。
   - 返回 `FAILED_PRECONDITION`（无实体文件）、跨租户或无权限：记为「未读」及原因，其余照常，不绕道读文件。
2.5 **联网补公开信息**：站内材料往往停在几年前。读完后联网查本公司的最新公开信息，把能补的都补上：
   - 查什么：上市 / 挂牌公司最近的年报、半年报、季报和重要公告（财务、股权、实控人、募投、诉讼处罚）；工商现状（现名、注册资本、股东、更名迁址）；近两三年的融资、并购、重大合同、资质；负面舆情。
   - 去哪查：优先巨潮资讯、交易所、全国股转、公司官网公告、国家企业信用信息公示系统；其次天眼查 / 企查查等工商公开页、权威财经媒体。用公司全称检索，主体对不上的不用。搜索摘要不算，要打开原文。
   - 怎么用：外部数字写明出处时点（如「据公司 2025 年年度报告」），与站内材料不一致时两者都写、注明差异，不替换站内事实。底稿逐条记 URL、发布日期、原文摘录。查不到的再写「待补」。
3. **定写法和版式**（先读 [DD-REPORT-WRITING.md](DD-REPORT-WRITING.md) 第 0 节）：
   ① 不带 `projectId` 搜「尽调报告 / 投资建议书 / 尽职调查 / 投资分析报告」等，挑 1–3 份最完整的读全文，学结构和用词，以它为准；
   ② 版式：挑本机构自己写的**同类报告** `.docx` 当范本，fileId 按优先顺序交给第 6 步 `agent_report_word` 的 `styleFileIds`，由服务端取范本并沿用版式（取不到的自动换下一份，都取不到用内置模板），**不停下来问用户**，也不用自己下载。
      - 同类：写投资建议书用站内的「投资建议书」，写尽调报告用「尽调报告 / 尽职调查报告 / 投资分析报告」；同一项目以往的同类 `.docx` 排最前，其次其他项目的，较新、较完整的在前，给 2–3 份。
      - 不当版式范本：会计师、律所等第三方出的财务尽调、法律尽调、审计报告，以及 BP、访谈纪要、清单、`.doc` 老格式。它们是别家的格式，本项目的这类文件只当事实材料读。
      - 交付时说明版式用的是哪份；`style.fileName` 不是同类报告时，换范本重新生成。
   ③ 站内找不到可读的范本，写法用 DD-REPORT-WRITING.md 第 1–11 节兜底，同样不停下来问。用户事先给了模板或范本时以用户的为准。
   范本只学写法和版式，不搬它的公司事实和数字。
4. **写报告**：按 Markdown 写到本地文件（`#` 一级、`##` 二级、`###` 三级标题，表格用 `|` 表格，表题单独一行写「表n：名称」，金额表上方单独一行写「单位：万元」）。事实和数字只用第 2 步读回的本项目材料和第 2.5 步查到的公开原文。
   - 材料和公开原文里都没有的，在缺信息的那一处写「待补」，不推算、不凭记忆补；问题清单只放需向企业核实的事项。
   - 正文不加引文、脚注、来源表、「编制说明」等证明或免责文字。
   - 另存工作底稿：每个事实或数字 → 文档名、fileId（公开信息记 URL 和发布日期）、原文逐字摘录、自算数的算式，只供自检，不放进报告。
5. **自检**：按 DD-REPORT-WRITING.md 第 12 节逐条核对，每个数字都能在材料或公开原文里找到，或由其算出，不过就改到过为止，不交半成品。
6. **生成 Word**：把第 4 步的 Markdown 全文作为 `markdown` 传给 `agent_report_word({ markdown, company, title, org?, styleFileIds })`，`title` 写「尽职调查报告」或「投资建议书」。服务端沿用范本的字体、标题编号、页面和页眉页脚，自动加封面和目录，Markdown 表格转成 Word 表格，返回 `url`（浏览器直接下载，30 分钟有效）。
   - 用户给了自己电脑上的模板：把文件读成 base64 作为 `styleDocxBase64` 传（10MB 以内），优先于站内范本。
   - **Word 只用这个工具生成**：不用 MiniMax 等其他 Word / docx 技能，也不自己写脚本拼 docx。别的工具不会沿用站内范本版式，也不认这里的标题、表题和单位写法。
   - 返回的 `style` 说明版式来源（`site` 带范本文档名和 fileId，`user-template` 是用户模板，`built-in-template` 是内置模板），`stylesSkipped` 列出没取到的范本及原因，交付时照实说明；`style.fileName` 不是同类报告时换范本重新生成。

## 交付

- **交给用户的是 Word 下载链接**：把第 6 步返回的 `url` 写成可点击链接，如「[下载《某某投资建议书初稿》](url)」，并说明 30 分钟内有效、过期可让你重新生成。对话里只写一段摘要（投什么、多少、估值、结论），不再贴全文。
- 交付消息里（不写进报告）说明：版式用的哪份（站内范本文档名 + fileId / 用户模板 / 内置模板）；写法参照了哪份；这是初稿、待投资经理复核；未读文档及原因；哪些内容来自联网公开信息；「待补」清单；材料是模拟或测试数据时一并说明。
