# 定级规则（主流程第 4 步）

阈值以 `agent_risk_threshold_get` 返回为准（`*_medium` / `*_high` 是降幅百分点，`debt_ratio_warn` 是资产负债率，`report_due_days` / `report_due_days_q4` 是季末后天数）。下文括号里的数字是默认值，租户改过就用租户值。每条预警写明命中哪一条。

## 高 high（网页显示「重大」）

- 失信被执行人 / 限制高消费；破产、重整、清算；实控人被采取强制措施；严重违法失信名单。
- 净资产转负。
- 降幅达到对应 `*_high`（默认 50%）：营收同比（`income_yoy_high`）、营收环比（`income_high`）；净利润（`profit_high`）、净资产（`net_assets_high`）、总资产（`total_assets_high`）较上期或上年末；季度数据里有货币资金时，货币资金较上期（`cash_high`）。
- 退市：交易所已作出终止上市决定、已进入退市整理期、新三板终止挂牌。

## 中 medium（网页显示「警告」）

- 新增被执行或作被告的重大诉讼；行政处罚；经营异常名录；核心高管离职公告；≥2 家独立媒体的负面报道。
- 上面各项降幅落在对应 `*_medium` 与 `*_high` 之间（默认 30%–50%，含下限不含上限）。
- 连续 2 季亏损且扩大；资产负债率 > `debt_ratio_warn`（70%）；季报逾期未报（判法见下）。
- 退市风险：被实施 *ST、收到终止上市事先告知书（交易所尚未作出决定）。

## 低 low（网页显示「警告」）

- 只有 1 家媒体的负面报道；轻微处罚；关键指标波动 15% 到中档下限之间。

## 计算口径

- 同比 = 本期（`type=current`）÷ 去年同期（`type=samePeriod`）− 1。降幅 =（基期 − 本期）÷ 基期 × 100%，基期必须 > 0；基期为负或 0 不算降幅（亏损扩大走「连续 2 季亏损且扩大」）。
- 边界：29.99% → 低，30% → 中，49.99% → 中，50% → 高（以默认阈值为例）。降幅超过中档下限就按中 / 高定，不得因「没有对应档位」降级。
- 净资产、总资产是时点数，有本期 + 上期或上年末两期就能定级；同比缺去年同期、连续两季缺单季数据，又没有公告数据可用时，标「数据不足」，不定级。财务类至少要 2 季数据（`financeQuarterCount`）。
- 优先用 `agent_portfolio_quarterly` 读回的数；自己算的数写明算式。
- **上市 / 挂牌公司的公告数据**：库里该季没有财务数据（或不足 2 期）时，公司正式披露的定期报告、业绩预告 / 快报里的同比数，同样按上面的阈值定级（如归母净利润同比 −39.58% → 落在 30%–50% → 中）。
  - 只用公告原文里直接写出的同比增减，不拿两份公告自己拼算；写明口径（「前三季度累计」还是「第三季度单季」），累计和单季走向相反时两个都写进事件描述，按累计数定级。
  - 出处用外网出处：优先巨潮资讯、交易所、公司官网公告原文，打不开时可用全文转载公告的财经网站公告页；摘录必须含该指标名和数字。`riskType` 写「财务」（写「公告」会被网页归到「法律合规风险」），`rule` 写命中的阈值条款。
  - 库里有该季财务数据时以库里的为准（服务端会按库里数据复核档位）。

## 退市按进程阶段定级

- 看交易所是否已作出决定：标题是「拟…终止上市」「终止上市事先告知书」的仍是告知阶段，算中，即使正文出现「终止上市决定」字样也不升高。
- 同一退市进程（*ST → 事先告知书 → 终止上市决定 → 退市整理期 → 摘牌）按已到达的最高阶段只算 1 条，*ST 不另记；之前各阶段写进事件描述，各阶段公告都作为出处并列；摘牌不另立一条。
- 只有 ST（无星号）、撤销或申请撤销退市风险警示，不命中退市条款。
- 引起退市的原因事件（如欺诈发行被行政处罚）按原条款另定一条，不与退市合并。
- 例：元道通信 2026-09-21 收到深交所终止上市决定 → 高（重大）。

## 季报逾期未报

截止日 = 季末 + `report_due_days` 天（四季度用 `report_due_days_q4`），截止日当天不算逾期。只有运行日已过截止日、且 `agent_portfolio_quarterly` 返回的 `reports` 里**没有**该季度记录，才算逾期。

- 有该季度记录就是已报，不论 `status`（2 审批通过、1 审批中、0 初始、3 不通过、7 撤回），`status=2` 绝不能判逾期。
- `update_date` 是记录最后修改时间，不是报送时间，不能拿它和截止日比，也不能据此写「迟报」「逾期 N 天」。
- 正例：运行日 2026-11-02，2026Q3 截止日 = 2026-09-30 + 30 天 = 2026-10-30，`reports` 里没有 2026Q3 → 中「季报逾期未报」，写入时出处传 `{ kind: "missing_quarterly_report", quarter: "2026Q3" }`（见 [WRITE.md](WRITE.md)），报告里写「agent_portfolio_quarterly 无 2026Q3 记录；截止 2026-10-30」。
- 反例：`reports` 里有 2026Q3（status=2，update_date 2026-10-31），写成「超截止日 1 天，季报逾期」→ 错，该季已报，不出这条。

## 其他

- 同一事件多个来源只算 1 条，出处并列。
- 初判与网页显示的对应：high → 重大，medium、low → 警告；「正常」永不写入。报告和确认卡写「初判 高/中/低 → 网页显示 重大/警告」，不自造等级名。
